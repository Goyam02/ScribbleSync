Architecture

Built around state, not UI.

ScribbleSync separates application state from rendering and persistence. CanvasManager owns the board while HistoryEngine handles actions and workers handle background processing.

Cross-tab communication is handled by BroadcastChannel, while local persistence uses localStorage.

The result is a small but layered architecture that demonstrates how browser APIs can work together without an external framework.

Engineering Concepts

Technologies with a reason.

Each browser API solves a specific problem inside the application.

Private Class Fields Protect internal board state and enforce controlled mutations.
Generators Step through action history for replay, undo, and redo.
Web Workers Move serialization and background processing away from the main UI path.
BroadcastChannel Communicate board actions between independent browser tabs.
localStorage Persist board snapshots locally between page reloads.
Promise Queues Serialize asynchronous saves so operations execute in order.
Cookies Represent a small simulated authentication session separately from application state.
Browser Notifications Surface remote changes when the workspace is running in the background.
